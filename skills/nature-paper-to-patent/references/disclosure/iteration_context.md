# Iteration context — read before merging or correcting

English translation by OC Science Lab, 2026-09-09. Original terms apply.

## Purpose

Define **what to do first and what to deliver during iteration**, preventing the agent from reading a merge/correction template but then repeating **Step 3–4 patent-point analysis**, or vaguely “updating the analysis” without saving a revised draft.

## When to read

When the user is clearly continuing work on an **existing disclosure or previously delivered draft**—adding material, changing sections, correcting errors or adjusting protection-point wording—read this document **before `merger.md` or `correction_handler.md`**, then read the relevant iteration template.

| Intent | Next template |
|---|---|
| Add documents, extend the solution or merge new material | `merger.md` |
| Correct an error, factual/parameter mismatch, style issue or protection-point wording | `correction_handler.md` |
| The user has specified emphasis under `disclosure_builder.md` §7.6 and only wants **chapter 5 strengthened in claim language**. The emphasis must match the draft's material and the positions already stated in chapters 5 and 3; do not invent scenarios merely to create choices. | `merger.md`: use the latest final draft; mostly change chapter 5, with small chapter 4/5 transition edits if needed |

## Inputs and outputs

**Inputs**

- This round's conversational instructions, mentioned files or pasted excerpts.
- **Read** the baseline disclosure `.md`, using the path supplied by the user or already present in the conversation.

**Outputs**

- Save the full merge or correction as **new files**, without overwriting the old draft by default: **`{normalized_case_name}_{YYYYMMDDHHmmss}.md`** and the matching `.docx` generated by **`mermaid_render.py`**.
- Use the **same naming rule as Step 7's first final draft**: every saved delivery has a timestamp. See `disclosure_builder.md` §7.3, item 5.
- Keep old `.md`/`.docx` versions in the same directory for comparison; overwrite only if explicitly requested.

Version history consists of multiple timestamped files in the same directory. No `iterations/` directory or snapshot script is required.

### Revision dialogue record — required separate Markdown

After every merge or correction and after writing the new `.md`/`.docx`, maintain **one fixed log** in the **case output directory**, alongside that delivery, for example `outputs/{case_id}/`.

- Use `disclosure_revision_log.md` in this English overlay by passing `--log-name disclosure_revision_log.md`. The upstream default is the Chinese filename `交底书修订对话记录.md`; existing logs with that name remain valid.

**Each entry must contain:**

1. **Recorded time:** both **local time and UTC**. The script generates both; include both for manual entries too.
2. **Type:** merge iteration or correction iteration.
3. **User-instruction summary:** this round's intent and key points, optionally including named files.
4. **Delivered files:** the new timestamped `.md` and `.docx` filenames.
5. **Merge/correction summary excerpt:** identical to, or a shortened version of, the response's “Merge summary (for the record)” or “Correction summary (for the record)”.

**Recommended:** after saving the delivery and generating Word, execute:

```text
python3 "$OCSL_WRITING_HOME/skills/nature-paper-to-patent/scripts/disclosure/iteration_dialog_log.py" --case-dir "{case_directory}" --log-name disclosure_revision_log.md --kind merge --user "{instruction_summary}" --summary "{summary_excerpt}" --artifacts "{case_timestamp.md},{case_timestamp.docx}"
```

Use `--kind correct` for corrections. If the script cannot run, **read** the existing log or **create** it if absent, then **append** an entry with the same fields; timestamps must be real.

Do not deliver an iteration without updating this dialogue record.

## Suggested sequence

1. Read this document, select the applicable merge/correction template and read it.
2. Read the baseline draft and supplementary material.
3. Complete the merge or correction, including self-checks **8.2 and 8.3** in `disclosure_self_check.md`.
4. Write the new timestamped `.md`, then run **`mermaid_render.py -o`** to create final figures and `.docx`.
5. Append the dialogue log using `iteration_dialog_log.py` or manually, as above.
6. In the response, give new file paths and the template's required merge/correction summary section.

## Prohibited shortcut

Do not recognize an iteration request, omit the merge/correction and new timestamped files, and instead repeat full patent-point discovery or return only analysis paragraphs.

Exception: if the user explicitly asks to discover patentable points again or restart prior-art searching, return to the main workflow from Step 3.
